# Project Handoff Checklist

Use this checklist when moving work between stages or teams.

- [ ] Clear acceptance criteria documented and attached
- [ ] Owner (role) identified for next step
- [ ] Relevant artifacts present:
  - [ ] Requirements / user stories
  - [ ] Designs / prototypes (if applicable)
  - [ ] Test plans / test cases
  - [ ] Deployment/runbook notes (if applicable)
- [ ] Environments available, with access verified
- [ ] Known risks and mitigation steps documented
- [ ] Dependencies and blocking issues listed
- [ ] Release window or date confirmed (if applicable)
- [ ] Stakeholders notified of handoff
- [ ] Person accountable for unresolved items before handoff identified
- [ ] QA sign-off criteria and automation status recorded

Place this checklist in the relevant ticket and attach to the release notes or handoff documentation.
